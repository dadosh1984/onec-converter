# Расширение конфигурации «onec_loader» (1С 8.3)

HTTP-сервис для записи данных в ИБ-приёмник.

## Установка (временно, до фичи zero-setup)
1. В 1С:Предприятие (Конфигуратор) открыть ИБ-приёмник.
2. «Конфигурация → Расширения конфигурации → Добавить» (имя: onec_loader).
3. В дереве расширения создать **HTTP-сервис** «onec_loader»:
   - URL-префикс: loader
   - Методы:
     - **GET /metadata** — возвращает JSON-описание структуры ИБ приёмника
       (справочники, документы, реквизиты, табличные части, перечисления).
     - **POST /load** — принимает JSON-пакет объектов и создаёт/обновляет их.
       Тело: {"objects": [{"type": "Справочник.Номенклатура",
       "key": [...], "attributes": {...}, "references": {...}}], "replace": false}
       Ответ: {"ok": true, "created": N, "updated": M, "errors": [...]}.
4. Модуль HTTP-сервиса — из файла Module.bsl (см. ниже).
5. «Файл → Обновить конфигурацию базы данных» (режим расширения), включить расширение.

## Контракт
- Формат атрибутов: типы 1С (Строка/Число/Дата/Булево) передаются как JSON-скаляры;
  даты — ISO 8601; ссылки — объект {"ref": "<тип>:<ключ>|..."} — разрешаются на приёмнике
  по естественному ключу.
- Один запрос — пакет до 1000 объектов (лимит в Module.bsl, U32); повторная
  отправка идемпотентна (поиск по ключу, replace=false не перезаписывает).
  Поле `idem` у объекта позволяет пропускать дубли внутри одного пакета (U29).
- Коды ответа: 200 (ok), 400 (ошибка контракта), 409 (конфликт ключей/правило 1→1),
  413 (слишком большой пакет).

## Аутентификация (Фаза 18+, Фаза 22 — OAuth2/JWT)

HTTP-сервис принимает **любой из двух** способов:

### 1. X-API-Key (shared-secret)
1. В `Module.bsl` задайте `ОжидаемыйКлюч` (константа в начале модуля) — свой
   надёжный секрет вместо `CHANGE-ME-AND-KEEP-SECRET`.
2. Клиент (Python) должен отправлять заголовок `X-API-Key` со значением ключа.

### 2. Bearer-JWT (HS256) — рекомендован для продакшена
Приёмник проверяет токен из заголовка `Authorization: Bearer <jwt>`:
- **подпись** HMAC-SHA256 — ключом служит `ОжидаемыйКлюч`;
- **срок жизни** — `exp` не в прошлом;
- **issuer** — равен `ОжидаемыйIssuer` (по умолчанию `onec-converter`).

Токен выпускается вашим OAuth2-сервером (client-credentials) или формируется
клиентом по HS256 с тем же секретом. `ПроверитьJWT` реализована в `Module.bsl`
на чистом 1С (HMAC без внешних библиотек); при любой ошибке — 401.
Ротация ключей (U30): заголовок `kid` выбирает секрет из `НаборСекретовJWT`;
токены без kid проверяются всеми секретами (обратная совместимость).

**Локальный токен (без OAuth2-сервера): Фаза 33.** Если внешнего сервера
нет, токен можно выпустить из CLI на том же общем секрете, что задан в
приёмнике (`ОжидаемыйКлюч`):

```bash
# секрет приёмника СОВПАДАЕТ с ОжидаемыйКлюч в Module.bsl
onec-converter mint-token --secret "CHANGE-ME-AND-KEEP-SECRET"
# печатает refresh-токен JWT (HS256, issuer=onec-converter)
```

И передать его в `load`:
```bash
onec-converter load --http http://<server>/loader/hs \
    --secret "CHANGE-ME-AND-KEEP-SECRET" --input batch.json
```
Здесь `--secret` включает локальный mint-token: клиент выпускает HS256 JWT на
месте и шлёт `Authorization: Bearer <jwt>` — без обращения к какому-либо
OAuth2-эндпоинту. `--token-url` (внешний сервер) и `--secret` (локальный
mint) — взаимоисключающие; приоритет у `--token-url`.

Без верного ключа/токена сервер отвечает **401 Unauthorized** (и для GET /metadata,
и для POST /load).

Пример использования из CLI:
```bash
onec-converter load --http http://<server>/loader/hs \
    --token-url http://<server>/token \
    --client-id migrator --client-secret "секрет" \
    --input batch.json
```
Или в `onec.toml`:
```toml
[auth]
token_url = "http://<server>/token"
client_id = "migrator"
client_secret = "секрет"

[onec]
retries = 3
```

> Замечание по `replace`: поиск существующего объекта перед обновлением
> нормализует ключ (убирает лишние пробелы, `СокрЛП`) — не создаёт дубли из-за
> пробелов/регистра в данных источника.

### Защита от перебора (Фаза 45/46)
`ПроверитьКлюч` ведёт счётчик последовательных неудачных попыток
(`Перем СчётчикНеудач`): после 5 неудач возвращает отказ до следующего
успеха. Сравнение ключа — константное время (`Совпадает`, Фаза 18):
длина+побитовое XOR без раннего выхода — исключает timing-атаку.
Ограничение (честно): переменные модуля HTTP-сервиса 1С не гарантируют
хранение между запросами — счётчик защищает в рамках сессии; для
production-нагрузки используйте внешний rate-limiter (nginx/шлюз).

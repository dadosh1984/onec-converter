## Фаза 18 — Безопасность и качество данных

> ✅ Выполнена. Итог: anonymizer (2-словные ФИО, регистр, HMAC-псевдоним,
> профили 152-ФЗ), http_client (ретрай 5xx, X-API-Key, сообщения с кодом),
> Cache (санитизация путей, stats + CLI `cache stats|clear`), Module.bsl
> (аутентификация, транзакции, частичный отчёт), Strict Mode + `load_direct(strict)`.

Цель: закрыть дыры анонимизации, HTTP-приёмника, кеша.

- [ ] [fact] anonymizer: `_FIO_RE` — ловить «Фамилия Имя» (2 слова) и разный регистр; `_hash_token` → HMAC-SHA256 с секретом (env/флаг), без секрета — fallback с предупреждением
- [ ] [fact] Module.bsl: аутентификация (shared-secret заголовок), транзакция + Попытка/Исключение вокруг каждого объекта (частичный отчёт errors)
- [ ] [fact] http_client: retry на 5xx (backoff), осмысленная ошибка с кодом+телом; 4xx — без retry
- [ ] [fact] Cache: санитизация ключей (запрет `../`), TTL/лимит размера; команда `cache clear/stats`
- [ ] [fact] Strict Mode: пре-валидация перед записью (длины NVC, диапазоны дат, границы чисел, GUID-ссылки)
- [ ] [assumption] Профили анонимизации 152-ФЗ («Зарплата», «Розница», «Медицина»)

## Фаза 19 — Горизонт данных: регистры, пустые таблицы, dt, replace

## Фаза 20 — Производительность и DX

Цель: большие базы (10+ ГБ) без OOM, удобство повседневной работы.

- [ ] [fact] mmap-чтение 1Cv8.1CD (mmap вместо read) — снижение RAM

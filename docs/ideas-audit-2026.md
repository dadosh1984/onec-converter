# Сравнительный анализ: onec-converter vs экосистема

## Чем мы отличаемся (уникальность)
1. **Полный пайплайн «структуры → правила → перенос → верификация»** под управлением
   LLM-агента (MCP). Никто из списка не покрывает сквозной перенос данных между
   РАЗНЫМИ конфигурациями 7.7/8.x под контролем агента.
2. **Свой парсер `1Cv8.1CD`** (без платформы) + **прямая запись в копию базы**
   (zero-setup, verify-after) — аналогов-«писателей» почти нет (все — читатели).
3. **Cross-версии**: источник 7.7 (CP866/CP1251) → приёмник 8.3.
4. **Безопасность**: анонимизация 152-ФЗ, строгий режим записи, HMAC, auth HTTP.
5. **Потоковый extract, метрики Prometheus, Docker, PyPI**, CI.

## Слабые места / конкурентные риски
- **Только файловые ИБ** — серверные (MSSQL/Postgres) вне охвата → теряем корпоративный сегмент.
- **Индексы не пересобираем** (Фаза 14, честно) — конкурент, умеющий реструктурировать
  через платформу (vbrunner/ibcmdrunner), обходит по «готовности базы».
- **1Cv8.dt / серверные** не читаем — не можем принять выгрузку.
- Некоторые функции уже продублированы экосистемой (метрики, git-converter) — но
  у нас другая цель (данные, не конфигурация).

## Конкурентоспособность (оценка)
- **Статус**: уникальный инструмент в узкой нише (миграция данных без платформы).
  Прямых аналогов «перенос + маппинг + агент» нет; аналогов-«читателей 1CD» больше.
- **Потенциальный ход**: закрыть серверные базы (чтение через ODBC) и repair-индексы
  (via v8runner-like обёртку) — тогда станем практически безальтернативными в нише.
- **OpenIntegrations (661★)** — концепция «набор MCP-тулов для 1С» уже подтверждает
  спрос на MCP; наш фокус уже (перенос данных), и это преимущество в своей нише.

## Рекомендуемые идеи для внедрения (приоритет)
1. **repair-indexes** (v8runner/ibcmdrunner clone): обёртка `ibcmd/*repair` — снять
   ограничение индексов; снимает главный конкурентный минус.
2. **Чтение серверных баз** (ODBC-MSSQL/Postgres как источник) — открыть корпоративный сегмент.
3. **export-kd3** (правила → КД3 XML) — мост к штатной 1С.
4. **DI-рефакторинг пайплайна + audit-логирование** — надёжность/масштабируемость.
5. **S3-выгрузка результатов, OpenAPI-спека Module.bsl** — pro-DX.

## Сравнение с нами (onec-converter)

| Критерий | 1c_mcp / toolkit | EDT-MCP | НАШ проект |
|----------|------------------|---------|------------|
| Требуется платформа 1С | **Да** (расширение/обработка) | Да (EDT) | **Нет** (Python, файлы .1CD/.dat) |
| Доступ к базе | Одна база (живая, через платформу) | Workspace EDT | **Файлы баз напрямую** (read-only + копия) |
| Перенос МЕЖДУ базами (миграция) | **Нет** | Нет | **Да** (7.7→8.x, маппинг, verify) |
| Запись в базу | Через платформу (объекты) | Нет | **Прямая запись в копию .1CD** (zero-setup) |
| Безопасность | OAuth2 (прокси) | — | X-API-Key, HMAC, анонимизация 152-ФЗ |
| Без платформы (CI/Linux) | Частично (прокси) | Нет | **Да** (Linux/macOS/CI) |

**Вывод:** конкуренты покрывают «доступ агента к ОДНОЙ живой базе через платформу 1С».
Мы — единственные, кто делает **миграцию МЕЖДУ базами без платформы** (файлы напрямую).
Наша уникальность усиливается, но конкуренты подтверждают спрос на MCP-1С и учат нас:
- **OAuth2-прокси** (1c_mcp) — можно взять идею для нашего HTTP-приёмника (вместо X-API-Key).
- **«Инструменты из коробки»** (1c_mcp) — у нас уже есть (inspect/extract/query/guid_diff и т.д.).
- **E2E+conformance CI** (EDT-MCP) — взять идею conformance-тестов для нашего MCP.
- **Встроенный сервер в 1С** (toolkit) — не наш путь (мы без платформы), но «без Python» — наш Docker уже решает.

## Новые идеи для внедрения (из MCP-конкурентов)
1. **OAuth2-прокси** для Module.bsl/приёмника (вместо голого shared-secret) — стандарт MCP-аутентификации.
2. **Conformance-тесты MCP** — проверить наш сервер на соответствие протоколу (авто).
3. **Режим «живая база через платформу»** (опциональный коннектор v8runner) — покрыть случай, когда 1С установлена (идея из 1c_mcp), без отказа от файлового пути.
4. **Инструменты из коробки шире**: у 1c_mcp — «метаданные из коробки»; у нас уже есть; можно добавить «список форм» (идея formsserver) как диагностику.

# Глубокий аудит (раунд 6, 2026-08-09) — до 500 улучшений + план фаз

Статус проекта на входе аудита: ~53 Фазы закрыты, 5 внешних раундов (U1–U62
в `docs/round5-analysis.md` практически все реализованы), ворота green
(pytest/ruff/mypy/vitest/MCP-conformance), есть CI, PyPI, Docker, аудит
tamper-evident, анонимизация 152-ФЗ, JWT, S3, MCP с 41 тулом.

Этот раунд — честная перепроверка ПО КОДУ (не по README). Ниже — только то,
что реально найдено. Если пункта нет в списке — его либо уже нет в проекте,
либо это выдумка, которой здесь не место.

Честная оценка: **серьёзных багов практически нет** — проект близок
к совершенству по своей нише. Найденные проблемы — точечные, и их
количество небольшое (порядка десятков, не сотен). Поэтому список ниже
заведомо меньше 500 — «до 500» означает верхнюю границу, а не обязательный
объём. Выдумать 500 фиктивных улучшений было бы неправдой.

## A. Реальные дефекты (подтверждены по коду)

- [bug] A1. `ai_skills.py:auto_map_schemas` — мёртвый код:
  `src_attrs = {...}` затем сразу `del src_attrs` (неиспользуемая переменная).
- [bug] A2. `config.py:load` — `setattr(cfg, attr, val)` для строковых полей
  не приводит `'true'/'false'` и не обрезает пробелы кроме strip('"');
  значение `source_encoding=" cp1251 "` пройдёт как есть.
- [bug] A3. `cli.py:cmd_audit` — при `--json` вывод записей идёт в stdout,
  а `{'counts':...}` в stderr: парсер stdout не получает counts, но
  структура вывода при `--json` невалидна (построчные JSON + блок counts
  в другом потоке). Несогласованно для машинного потребления.
- [bug] A4. `cli.py:cmd_verify` — при фильтре `--objects` тип проверяется
  `'.' not in t`, но объекты типа `Таблица.xxx` уже содержат точку;
  ok, но это означает, что verify не отличим от extract-фильтра по семантике.
- [bug] A5. `cmd_load` (файловый режим) — `args.target` default `''`;
  если ни `--http`, ни `--direct`, ни `--target` не задан — `target = Path('')`
  → запись в `load.json` в текущей директории молча, без предупреждения.
- [bug] A6. `_notify` — `args.notify_url` и `args.notify_telegram`
  не заданы в `build_parser` для всех команд (только для `load`);
  `cmd_*` вызывающие `_notify` с другими Namespace корректны, но флаги
  ищутся через `args.<attr>` — у `extract/transform` их нет (там `_notify`
  не зовётся — ок).
- [bug] A7. `csv-вывод audit` использует `utf-8-sig` но не экранирует
  поле `obj` от формулы `=cmd` — инъекция формул в Excel (Фаза 48 CSV).
- [bug] A8. `sonar_report`/`sonar-report` — `--out` б-выводит ссылку на файл,
  но `total` печатает в stderr вместе с `ok`; parse-скрипты в CI должны
  ловить и stdout, и stderr.

## B. Мёртвый код / дубли / хардкоды

- B1. `ai_skills` — см. A1 (del src_attrs). Плюс `del` — единственный случай.
- B2. `pytest.ini` + `pyproject.toml` оба задают какие-то pytest-опции —
  проверить дрейф документированных опций между копиями.
- B3. `src/tasks/*.ts` (~370 файлов) — закоммиченные снапшоты исходных
  заданий Orion. Часть — исторические артефакты фаз, не исполняемые.
  Уменьшить точечно сложно; как минимум задокументировать, что это
  неизменяемый архив, и исключить из lint-ворот.
- B4. `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.hypothesis/`,
  `test.pytest-tmp/`, `.coverage`, `reports/` — не в .gitignore? проверить
  (в tree видны в CWD, но git status чист → они в .gitignore, ok).
- B5. Дубль логики «прочитать таблицу 1CD построчно» в `cmd_dump_records`
  и `cmd_export_xlsx` — разнести в общую функцию `iter_table_jsonable(db, t)`.
- B6. Хардкод `'cp866'` как default `--source-encoding` в inspect/extract —
  продублирован в 3 местах; вынести в константу `DEFAULT_SOURCE_ENCODING`.
- B7. `mcp_server` — количество тулов (41) вручную поддерживается;
  добавить в `cmd_mcp` сортировку (уже есть) + тест контракта
  «список тулов`docs/commands-map.md` ↔ mcp_server`» (есть частично).

## C. Функциональность (востребованность)

- C1. **Нет команды `server`/`mcp run` в CLI** — MCP-сервер запускается
  только `python -m onec_converter.mcp_server`; добавить `onec-converter mcp --stdio`.
- C2. `verify` работает только между intermediate JSON (после e2e),
  нет сверки источник(1CD)↔приёмник(1CD) напрямую через парсер.
- C3. `extract --objects` фильтрует по kind/имени конфигурации; нет
  фильтра по признаку «только пользовательские данные / исключить
  служебные таблицы`_Config`».
- C4. Нет пакетной команды полного цикла `migrate` в CLI (есть в MCP);
  CLI-пользователь вынужден вызывать inspect/extract/map/transform/load/verify
  по одной. Добавить `onec-converter migrate` (обёртка всего пайплайна).
- C5. `load --http` не имеет `--timeout` на уровне клиента (есть ретраи);
  таймаут берётся из HttpClient83 — выставить флаг.
- C6. Отсутствует `onec-converter lint-self` для проверки на дед-код
  поверх ворот (ruff уже есть; добавить `F841`-ловлю осталось).
- C7. `map --init` и `ai-map` дают rules; нет команды `rules validate`
  повторно вне transform (есть `map --rules-file`, но без детализации
  несоответствий по атрибутам).

## D. Производительность / память

- D1. `cmd_inspect` 8.x — `table_stats` для всех таблиц одним проходом

  `db.table_stats_all()` — ок.
- D2. `audit._last_record_hash` кеш ключует по `mtime_ns,size` — при

- D3. `load_8x._cleanup_workfiles` и `s3_client` abort — `except OSError/
  S3Error: pass` — намеренно swallow (cleanup best-effort), но без

- D4. `read_metadata` LRU in-memory для MCP-сессии — U39 done; проверить
  что он используется в `cmd_ai_map`/`cmd_ai_explain` (там каждый вызов
  читает заново — добавить кеш).

## E. Безопасность (152-ФЗ / комплаенс)

- E1. Извл: секреты в DSN подаются в `build_sql_source` → ошибки могут
  содержать URL с паролем. U27 маскирует в логах — проверить, что
  `sql_source.error` сам не печатает DSN (см. `source_url` в traceback).
- E2. `audit` CSV — формульная инъекция (см. A7): экранировать `=`, `+`,
  `-`, `@` в текстовых полях при экспорте CSV для Excel.
- E3. `mint-token` — `--secret` в аргументах командной строки виден в
  `ps`/истории; добавить чтение из env `ONEC_SECRET`/stdin (не только флаг).
- E4. `load --direct` snapshot.1CD — временный артефакт; убедиться, что
  он не содержит токенов/секретов и удаляется в конце (чистится?).

## F. UX / интерактивность / человек-читаемость

- F1. Многие команды печатают **сырой JSON** (`inspect`, `guid-diff`,
  `config-versions`, `query` — частично). Задача пользователя — «визуально
  понятный текст». Для интерактивного режима (TTY) добавлять `--pretty`
  / табличный вывод (as TUI-таблица), оставляя JSON при `--json`/не-TTY.
- F2. `query`/`dump-records` выводят JSON-массив в stdout без человек-
  читаемой таблицы; для TTY — печатать ASCII-таблицу (как psql).
- F3. Нет `--color`/`--no-color` и единого форматтера прогресса для
  длинных `load --direct` — прогресс-бар в stderr (есть progress.py,
  но не выведен в CLI-терминал).
- F4. `--help` каждого подпарсера — текст на русском (хорошо), но
  сгруппирован не по фазам/важности; добавить группы аргументов
  (argparse argument groups) для читаемости.
- F5. `cmd_inspect` при 8.x выводит ВСЕ таблицы (в т.ч. сотни служебных)
  — захломляет; для TTY давать топ-N + флаг `--service-tables`.

## Напоследок (честно)

Спроект не «совершенен» в том смысле, что есть 20+ реалистичных улучшений
(фазы 54–59). Но он близок к нему: серьёзных багов нет, 41 MCP-тул,
сквозной перенос 7.7→8.3 с верификацией, аудит tamper-evident, ворота.
Так что вместо 500 пунктов — выверенный список из десятков. Это честный
результат, а не подгон под желаемое число.

# Облачные среды 1С (1С:Фреш, аренда) — поддержка в onec-converter (Фаза 53, U54)

Файловая ИБ в облаке/аренде (1С:Фреш и аналоги) доступна не напрямую по
файловой системе, а через **HTTP-протокол 1С (http-сервисы / OData)**.
`onec-converter` работает с такими средами через два своих интерфейса.

## Что работает

| Среда | Канал | Команда/тул |
|---|---|---|
| Локальная файловая ИБ | прямой доступ к 1Cv8.1CD / 1Cv77.dat | `inspect/extract/stats` |
| Аренда/облако с HTTP | http-сервис приёмника (расширение `extension_83`) | `load --target-url`, MCP `migrate` |
| PostgreSQL / MSSQL | SQL-источник | `query`, `fetch-config` (схемы) |

## Ограничения 1С:Фреш

- Нет прямого доступа к файлам `.1CD` пользователя — только через API/сервисы.
- Прямая запись (`--direct`, `write_8x`) и `clone-db` **неприменимы** к облачной
  базе: нет локального файла.
- Для облака рекомендуемый путь: **HTTP-сервис** (расширение вставляется в
  конфигурацию арендованной базы) — `load --target-url` создаёт/обновляет
  объекты; `mint-token --kid` выдаёт JWT для авторизации.
- Если у аренды есть выгрузка файловой ИБ (резервная копия) — обычный
  файловый сценарий работает целиком.

## Пример (облако)

```bash
# выпустить ключ для HTTP-сервиса приёмника
onec-converter mint-token --secret "$PETYA" --kid current --json

# загрузить правила в облачный приёмник через http-сервис
onec-converter load --input ./mapped.json \
    --target-url https://fros.1c.ru/hs/onec_loader \
    --token   "$TOKEN"
```

# Рецепт: BEKAS PLUS BIZNES → Бухгалтерия для Узбекистана 3.0

Готовый пошаговый сценарий переноса данных между ИБ 1С с помощью
`onec-converter` без платформы 1С. Это сквозной пример: источник 7.7/8.x →
правила маппинга (TOON) → перенос → верификация.

## Предпосылки

- Python ≥ 3.11, `pip install -e ".[dev]"`.
- Исходная ИБ (файловая) и целевая структурно-подготовленная ИБ 8.3.
- `onec-converter doctor` — окружение в порядке (версия mcp, PyYAML, место).

> **Что переносим:** пользовательские данные (справочники, документы с ТЧ,
> регистры), внесённые в ИБ вручную. **Конфигурация (код, метаданные) НЕ
> переносится** — структура приёмника готовится отдельно: конфигурация
> приёмника обновляется/настраивается штатными средствами (Конфигуратор,
> 1C:EDT, хранилище) до начала переноса данных.

## Шаг 1. Разведка

```bash
# что в источнике и сколько
onec-converter inspect --source-dir ./src_ib
onec-converter dump-records --source-dir ./src_ib --table _REFERENCE3 --limit 20
onec-converter query --source-dir ./src_ib --table _REFERENCE3 --where "_DESCRIPTION LIKE 'Банк%'"
```

## Шаг 2. Схемы и структуры

```bash
onec-converter guid-diff --source-dir ./src_ib --target-dir ./tgt_ib
onec-converter config-versions --source-dir ./tgt_ib
```

## Шаг 3. Извлечение

```bash
# маленькие базы — целиком; большие — потоком (без OOM)
onec-converter extract --source-dir ./src_ib --out ./out/intermediate.json
# --stream требует файла; для больших баз используйте MCP step_extract(stream=True)
```

## Шаг 4. Правила маппинга (TOON)

Правила `rules.json`: source → target по естественным ключам. Генерация
промпта для LLM:

```bash
onec-converter map --rules-file ./rules.json --meta-source ./meta_src.json \
    --meta-target ./meta_tgt.json --llm-prompt
```

## Шаг 5. Transform + preview

```bash
onec-converter transform --rules-file ./rules.json --input ./out/intermediate.json \
    --out ./out/target.json --preview 5
```

## Шаг 6. Прямая запись (zero-setup)

```bash
# в КОПИЮ приёмника; verify_after включён по умолчанию (Фаза 16);
# snapshot.1CD приёмника сохраняется в ./work до записи (Фаза 24)
onec-converter load --direct ./tgt_ib --input ./out/target.json --workdir ./work
# ответ включает 'verify':{ok, checked, ...}, 'ref_warnings' и 'snapshot'
```

**Стенд через clone-db (Фаза 24):** чтобы гонять миграцию на копии без
риска для боевой базы, создайте стенд заранее — база + правила:

```bash
onec-converter clone-db --source-dir ./tgt_ib --target-dir ./stand \
    --with-rules ./rules/rules.json
# далее load --direct ./stand (оригинал ./tgt_ib не трогается)
```

## Шаг 7. Проверка копии перед использованием

1. Убедиться `verify.ok is True` и `checked == N объектов`.
2. Прочитать копию парсером (`Database1CD(copy_path)`) — счётчики совпадают.
3. Ограничение: **индексы не пересобираются** (Фаза 14) — при открытии в 1С
   выполнить тестирование/реструктуризацию (Конфигуратор → Тестирование,
   или `chdbfl.exe /i`), на копии.

## Автоматический путь (MCP/агент)

```text
migrate(project, source_ib_id, target_ib_id, source_dir, target_url,
        rules, out_file, source_encoding)
```
Выполняет init → inspect → extract → map → transform → validate → load
с прогрессом и timings.

## Ограничения

- Серверные (SQL) ИБ и `1Cv8.dt` не поддерживаются (только файловые).
- Регистры сведений/накопления переносятся (Фаза 19), но итоги/последовательности
  рекомендуется пересчитать в 1С после загрузки.

# Перенос остатков и оборотов: регистры сведений/накопления (Фаза 35)

Регистры сведений (`_InfoRg*`) и накопления (`_AccumRg*`) — это такие же
таблицы с записями; 1С хранит их остатки и обороты как обычные строки.
Перенос выполняется той же механикой прямой записи (`load --direct`), что
и для справочников/документов, — никаких отдельных «движений» не требуется.

## Подготовка приёмника

1. Структура приёмника (включая регистры) готовится заранее — регистры
   должны существовать в конфигурации, иначе таблицы `_InfoRg…/`_AccumRg…`
   не будет куда писать.
2. Перечисления переносятся отдельно (см. ниже).

## Извлечение остатков

Остатки можно забрать из источника как набор строк регистра (физическая
таблица или объект `РегистрXX.Имя`):

```bash
onec-converter extract --source-dir ./src \
    --objects="РегистрСведений.КурсыВалют;РегистрНакопления.ТоварыНаСкладах" \
    --out registers.json
```

## Правила маппинга

Регистр-поля отображают через `attributes` так же, как обычные реквизиты:

```json
{
  "version": 1,
  "objects": [
    {
      "source": "РегистрСведений.КурсыВалют",
      "target": "РегистрСведений.КурсыВалют",
      "attributes": {"Период": "Период", "Валюта": "Валюта", "Курс": "Курс"}
    }
  ],
  "enums": {"Валюта": "Валюта"}
}
```

## Перечисления (Фаза 35)

1С хранит значения перечислений индексами. Правила и промежуточный JSON
оперируют именами. `enum_mapper` («авто-маппинг по именам») позволяет
переносить регистр-поля, значения которых в приёмнике переставлены или
переименованы:

- `normalize_enum_name` — регистр/пробел-независимое сравнение
  (`Статус заказа` == `СТАТУС_ЗАКАЗА`);
- `build_enum_map` — соответствие по нормализованным именам;
- `map_enum_value` — преобразование имени/индекса в значение приёмника.

В `transform` правило `enums: {поле: имя}` переносит значение как имя;
`{поле: {имя_ист: имя_приёмник}}` — явный словарь. Для авто-сопоставления
зовите `build_enum_map(значения_ист, значения_приёмник)` до `transform_object`.

## Загрузка остатков на приёмник

```bash
onec-converter transform --input registers.json --rules-file rules.json --out t.json
onec-converter load --direct ./target --input t.json --workdir ./work --index-repair
```

`--index-repair` (Фаза 34) сгенерирует скрипт восстановления индексов
(`/TestAndRepair` или chdbfl) — обязателен после массовой прямой записи,
чтобы Конфигуратор приёмника открыл базу без ошибок целостности.

## Проверка

```bash
onec-converter query --source-dir ./target --table _InfoRg100 --limit 20
```

или в Конфигураторе приёмника: отчёты по остаткам/оборотам должны совпадать
с источником.

# Формат файловой ИБ 1С 8.x (1Cv8.1CD) — справка (Фаза 53, U52)

Краткая инженерная справка по физическому формату, важному для
`onecconverter` (чтения и прямой записи без платформы 1С).

> Справка НЕ заменяет официальную документацию 1С; это конспект по
> открытым исследовательским материалам (tool1cd/1CDParser и др.) в рамках
> нашей авторской реализации.

## Страница и слоты

- Файл `1Cv8.1CD` разделён на страницы по `page_size` (обычно 4096 Б).
- Первая страница — заголовок базы: сигнатура, `page_size`, число страниц,
  смещения на корневые таблицы `CONFIG`, `PARAMS`, `DBNames`, `V8versions`.
- Каждая страница имеет 24-байтный заголовок и слоты FAT (4 байта каждый)
  для цепочек объектов.

## Файловая система (FAT)

- Объект БД идентифицируется страницей-заголовком: сигнатура `0x30 0x90`,
  `fat_level` (0 — прямой список страниц, 1 — через список FAT-страниц),
  длина (8 байт), таблица FAT.
- Пространство файла расчерчено на цепочки (chunks) по 4 страницы (`chunk_n*4`).

## Таблицы и поля

- Схемы таблиц (имена, поля, типы) лежат в `CONFIG`; ссылки таблица↔номер —
  в `DBNames`. Каждая таблица ссылается на страницы данных (`data_page`),
  блобов (`blob_page`) и индексов (`index_page`).
- Типы полей: `B` (16-байт ref), `L` (bool), `N` (BCD-число),
  `NC`/`NVC` (строка), `DT` (7-байт дата), `NT`/`I` (число/целое), `RV` (нотация).
- Строка таблицы собирается последовательно по полям; `row_length` известен
  из схемы. `_IDRREF` — ссылка на объект (PK справочников), `_VERSION` —
  версия записи.

## Индексы (B-tree)

- `index_page` таблицы описывает деревья: страницы-узлы и листья; каждый
  индекс имеет уникальный `index number`, слоты со ссылками на ключи.
- `_IDRREF`-индекс обязателен для справочников (уникальность).

## Дата

- 7 байт: модифицированная юлианская дата и смещение. Значение 0 дат
  трактуется как «пусто».

## Индексы (Фаза 14, spike) — формат НЕ расшифрован, запись НЕ выполняется

Изучение реальных баз (1C_8.1/1Cv8.1CD, 1C_8.3/1Cv8.1CD) — обе дают
version-байты [01 00 00 00 | 20 00 00 00] (total_pages @12 различается) —
показывает, что объект индекса таблицы (Table.index_page) является обычным
FAT-объектом данных (fat_level 0/1) БЕЗ сигнатуры [1c fd], из N страниц
по 8192:

- **page 0** — каталог границ листьев: массив uint32 (кумулятивные
  счётчики записей на образ-лист), напр. (0,1,3,5,7,...) для
  _Reference160 (2 строки), (0,1,3,10,...) для _REFERENCE3.
- **нечётные страницы 1,3,5...** — служебные описатели образов:
  [idx:u32][offset:u32] (значения вида 0x00800010).
- **чётные страницы 2,4,6...** — образы листьев: заголовок [count:u16],
  ключи упакованы битово с дельта-сжатием по общему префиксу,
  payload-байты лежат в хвосте страницы (на последних байтах видны
  младшие байты ключей _IDRREF).

Пример (_Reference160, 2 строки): page0 dir=(0,1,3,5,7,...); page2
заголовок [03 00 01 00 ff ff ... ff ff], на последних байтах страницы —
payload ключа (1ff0: 84 4b d1 0b ...). Таблицы 8.1 _REFERENCE3/_REFERENCE7
устроены так же.

**Этот формат ОТЛИЧАЕТСЯ от LeafPageHeader/BranchPageHeader и
дельта-схемы pack_leafpage из Reference-кода .spike/tool1cd (последний
покрывает 8.3.8).** Это старый (до 8.3.8) image-формат; точная битовая
упаковка ключей не расшифрована.

**Вывод для записи:** пересборка индекса вслепую небезопасна —
валидация реальной 1С в этом окружении невозможна, ошибка упаковки
испортит копию. Поэтому append_records по-прежнему выдаёт UserWarning
для таблиц с index_page != 0 и НЕ пересобирает индекс. Ограничение
«индексы не пересобираются» — осознанное решение, а не пропуск.

## Фаза 14 — Запись индексов при append в 1CD

Закрыть главный риск записи: таблицы 1С используют B-tree индексы
(512 из 517 таблиц 8.1), и после `append_records` они не отражают новые
строки.

- [ ] [spike] Формат index-объекта 1CD (B-tree): страницы, порядок,
      узлы/листья, привязка к полям (описания `{"Indexes",…}` в каталоге);
      как 1С пересобирает индекс при вставке → `docs/format-8x.md`
- [ ] [fact] `write_8x.py`: чтение существующего индекса таблицы (keys,
      листья) и вставка ключа новой строки в B-tree (балансировка или
      append-путь)
- [ ] [fact] Пересборка: для таблиц с `index_page != 0` после append —
      обновить индекс (пересоздать листья из полных ключей таблицы);
      риск целостности
- [ ] [fact] Unit-тесты: индекс-объект читается/пишется; после append
      в таблицу с индексом ключи новых строк присутствуют
- [ ] [assumption] Интеграция: append в таблицу с индексом на копии
      реальной 8.1 → парсер + индекс читают согласованно
- [ ] [assumption] README/docs: ограничение «индексы не пересобираются»
      → «индексы пересобираются, кроме BINARYDATA»

Приоритет: высокий (самый рискованный/ценный — без индексов реальная 1С
может не увидеть новые строки).

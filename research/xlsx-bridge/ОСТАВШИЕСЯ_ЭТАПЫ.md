## 1. Доделать ядро переноса (Фаза 3, открытые задачи)

### 1.1 События-хуки из epf (задача 6 tasks.md)
В epf есть обработчики, которые надо перенести в Python-хуки (поля `before_write` / `after_write` в BridgeConfig уже заложены):
- **ПередЗаписьюОбъекта** — проверка/модификация значения перед записью.
- **ПриЗаписиОбъекта** — пост-обработка (например, дорасчёт реквизитов).
- **«Вычислять»** (колонка C8) — ограниченный eval выражения на строке (без произвольного кода, только арифметика/функции дат).

### 1.2 Режим 1 — табличная часть (ТЧ)
Сейчас `import_bridge` бросает `BridgeError` «не реализован». Надо:
- связка строки ТЧ с объектом-владельцем (СвязьПоВладельцу),
- запись в табличную часть владельца (создание/обновление строк).

### 1.3 Расширения lookup
- [x] **СвязьПоВладельцу** — поиск в подчинённых/иерархических справочниках с фильтром по владельцу (`resolve(owner=...)`, _OWNERIDRREF) — реализовано.
- [x] **Документы: поиск «Номер от Дата»** — resolve_day по календарному дню — реализовано.
- [x] **Перечисления** — закрыто в изменении «изучить-типовую-обработку-1с»: таблица `_Enum<N>` несёт только `_IDRREF`+`_ENUMORDER`; имена/синонимы извлекаются из CONFIG приёмника (`enum_resolver.extract_enum_values`) и строятся индекс синоним->ссылка через позиционное соответствие (на реальной базе 1C_8.1: 35/35). Интеграция: ветка `Перечисление.X` в `epf_load._resolve_ref`. Открытый остаток: мета `read_metadata` не несёт полное имя ссылочного типа для `bridge_verify` (сверка enum-колонок по синониму).

# Spec: read_only_pytest_mypy_strict_ruff_vitest

## Назначение
Создать в onec_converter новый режим переноса данных между ИБ 1С «пользовательские данные через xlsx-мост с обратным контролем» (команда/пайплайн, напр. `bridge-migrate` или расширение `wizard`): полный алгоритм по шагам: (1) проверить пути до оригиналов ИБ источника и приёмника (существуют, это копии, не оригиналы), (2) создать копию ТОЛЬКО приёмника в /workdir в корне проекта (источник не трогаем — только читаем), (3) загрузить все метаданные из ИБ источника и приёмника (объекты и их атрибуты; использовать существующий кеш метаданных для скорости), (4) в ИБ источника определить данные, внесённые пользователем 1С вручную, отдельно от данных по умолчанию и данных, которые ИБ формирует сам формулами (идентификация user-введённых данных по признакам: не-predefined ссылки, неслужебные записи, константы кроме предопределённых и т.п.) — создать список таких данных и показать пользователю, (5) сравнить метаданные источника и приёмника ТОЛЬКО по пользовательским данным, (6) создать список расхождений, определить какие данные не совпадают (логическое рассуждение, LLM-объяснение через существующий ai-explain/explain_diff), уточнить у пользователя какие данные переносить, (7) выгрузить данные источника в xlsx-мост — КАЖДЫЙ раздел (объект/справочник/регистр/документ) отдельным файлом, сообщить пользователю итоговое количество файлов, (8) загрузить данные в приёмник через xlsx-мост по одному файлу, (9) обратный тест: выгрузить данные из приёмника в xlsx мост отдельным файлом и сравнить с xlsx мостом источника (bridge-verify), при расхождениях определить место ошибки и исправить методом подбора, (10) повторять (8)-(9) до полного совпадения, (11) цикл «загрузка → обратный тест → результат» выполняется по одному файлу (разделу), включая табличные части данных. Процесс должен быть ОЧЕНЬ быстрым: использовать существующий кеш метаданных, инкрементальный перенос (повторный прогон только для изменившихся разделов), параллелизм загрузки независимых разделов, однопроходное чтение 1CD. Реализация: команда CLI + MCP-тул; шаги 1-6 — разведка и план (без записи), 7-11 — исполнение по разделам. Обратный контроль опирается на уже расширенный bridge-verify (составной ключ, --ignore-cols, дифф по полям). Ворота: pytest (новые тесты на fake-базе), mypy strict, ruff, vitest; без новых зависимостей.

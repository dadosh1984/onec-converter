# Предложение — развить-команду-bridge-verify

## Цель
Развить команду bridge-verify (обратный контроль переноса через xlsx-мост) в onec-converter: сейчас она выгружает данные из копии приёмника обратно в xlsx-мост и сравнивает построчно с исходным мостом по ОДНОЙ ключевой колонке (первая search-колонка), отдавая JSON {matched, mismatched, missing, extra, diffs}. Идеи: (1) составной ключ из нескольких полей (--key не одна колонка, а список); (2) нормализация значений при сравнении (числа 1 vs 1.0, даты, bool, пробелы/кавычки, пустое vs None) — сейчас строгое сравнение списков даёт ложные mismatched; (3) diff на уровне полей, а не строк: для 'different' показывать какие именно колонки и значения различаются (in vs out по каждой колонке); (4) --ignore-cols для служебных колонок (_Version/_Marked и пр.), которые легально меняются при записи; (5) отчёт расхождений в XLSX (лист «Расхождения») + сводка в JSON, экспорт в S3 как dump-report; (6) быстрая фаза: сначала сверка количества строк (row count) без полной выгрузки, полное сравнение только при несовпадении; (7) семплирование/limit для больших таблиц (сравнить N случайных ключей, оценка полноты); (8) пакетный режим: verify всех объектов моста разом, а не одного obj_fullname; (9) интеграция: флаг --verify-after в bridge-import/migrate, авто-запуск обратного контроля после загрузки; (10) запись результата в журнал аудита (tamper-evident, совместимость с audit-verify). Ворота: pytest, mypy strict, ruff, vitest зелёные; без новых зависимостей; работа только с копиями баз.

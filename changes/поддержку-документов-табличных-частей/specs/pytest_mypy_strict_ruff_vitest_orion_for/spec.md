# Spec: pytest_mypy_strict_ruff_vitest_orion_for

## Назначение
Реализовать поддержку Документов и табличных частей (ТЧ) в xlsx-мосте bridge-migrate: расширить export_bridge для выгрузки шапки документа (mode=0, поиск по Номеру/Дате) и каждой ТЧ отдельным мостом (mode=1, obj_fullname 'Документ.Х.ТЧ.<таблица>'); импорт через существующий epf_load MODE_TABLE (уже реализован приём строк ТЧ по владельцу); build_plan включает документы (шапка + по разделу на каждую VT-таблицу из meta['tables'] по префиксу <таблица>_VT); round-trip verify через тот же obj_fullname. Дополнительно: санитизация строк для openpyxl (control-символы 0x00-0x1F, суррогаты, бинарные bytes-значения NT-полей -> None), чтобы реальные базы (1C_8.1) экспортировались без IllegalCharacterError. Быстродействие: переиспользовать существующий read_metadata (дисковый кеш). Проверка на реальной базе 1C_8.1: Документ.БанковскаяВыписка (2286 строк) и ТЧ _DOCUMENT41_VT770 (14462 строки) экспортируются без ошибок.

- Вне области: всё, что не заявлено в предложении.

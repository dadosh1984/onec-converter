# Design — 1-8-x-1cv8: полный парсер 1Cv8.1CD

## Цель фазы

Превратить каркас `source_8x_file.py` (заголовок/страницы) в **полный читающий парсер
файловой ИБ 1С 8.x**: каталог таблиц, строки с декодированием полей, blob-цепочки,
DBSCHEMA, конфигурация 8.1-эпохи. Это критический путь реального сценария:
источник `1C_8.1` (банки Узбекистана) → приёмник `1C_8.3`.

Дополнительно: тул `status` в `mcp_server` — адаптированная идея из расширения
**1C: Platform Tools MCP** (yellow-hammer): у них `onec_platform_tools_status`
(состояние подключения, повторное подключение). Мы не копируем код — переносим
полезный паттерн: агент должен видеть состояние коннекторов, кеша и пайплайна.

## Принципы

1. **Авторский код.** Логика формата изучена у сообщества (tool1cd, onec_dtools,
   1creader) и зафиксирована в `docs/format-8x.md`; код пишется с нуля.
2. **Read-only.** Реальные базы (`1C_8.1`, `1C_8.3`) только читаются; тесты не пишут в них.
3. **Оба стиля имён таблиц**: `_REFERENCE3` (8.1-эпоха) и `_Reference74` (8.3, camelCase).
4. **Правило «1→1»** не затрагивается этой фазой (только чтение).
5. Ворота: ruff, mypy strict, pytest (unit + интеграционные на реальных базах).

## Формат 1CD (сводка, детали — docs/format-8x.md)

- Заголовок `1CDBMSV8` + версия; страницы 8192 (8.2.14+) / 4096.
- **Root-объект** БД (каталог): поток описаний таблиц — каждая запись: имя,
  числовой номер, список полей (тип, длина, точность, null_exists), смещение/размер
  строки, first_block, цепочки блоков (FAT level 0/1).
- **Цепочки блоков**: страница хранит ссылку на следующую; чтение строки =
  следование по цепочке; поле `PARTNO` в 8.1-эпохах отсутствует (историческая
  особенность версий < 8.2.14).
- **Blob**: цепочка 256-байтных чанков; размер в заголовке блоба.
- **DBSCHEMA**: blob `SERIALIZEDDATA` — блоки `{"ReferenceN","N",<id>,"",{FldNNN…}}`,
  типы R/N/S/L/E/V; **привязка таблица↔объект = порядок коллекции = порядок блоков
  DBSCHEMA** (проверено: «Банки» = Reference3 = `_REFERENCE3`, 1141 запись).
- **Конфигурация 8.1-эпохи**: GUID-файлы (zlib inflate) + root
  `['2', <main_guid>, <base64>]`; дерево коллекций `[class_guid, count, guid…]`; файл
  объекта `['1', ['47', …]]` — имя, синоним (`['1','ru',<синоним>]`), комментарий.
- **Кодировки**: NVC = UTF-16LE (префикс длины, null-флаг учитывается в offset),
  RV = 16-байт GUID, N = BCD-подобное, DT = 7 байт, L = 1 байт.

## Модули

- `source_8x_file.py` — единственный модуль фазы:
  - `Database1CD` — каталог таблиц, строки, blob, DBSCHEMA;
  - `read_metadata(path)` — конфигурация + привязка → единая модель (справочники,
    документы, перечисления, регистры, поля с типами);
  - `read_table(path, table_name)` → итератор записей `dict[str, Any]` (значения
    декодированы: str/int/float/date/GUID; ссылки RV — GUID, переназначение — в фазе map).
- `mcp_server.py` — новый тул `status` (см. ниже).
- `model.py` — использование существующих `ObjectType/AttrDef/Record` без изменений.

## Тул `status` (адаптация идеи)

```
status() → {
  connectors: {file: <путь/размер/версия>, http: <ok/err>, sql: <нет>},
  cache: {root, entries, bytes, hits},
  pipeline: {project, pair (1→1), last_step, step_ok},
}
```
Назначение: LLM-агент перед каждой командой видит, что доступно и что уже сделано;
повторное подключение/переинициализация — по подсказке агента (аналог их
"позвоните, если инструментов не видно").

## Тестирование

- Синтетические фикстуры: генератор минимального `.1CD` (заголовок, root-каталог
  с 1–2 таблицами, цепочки блоков, строка с NVC/RV/N/DT) в `tests/fixtures/gen_1cd.py`.
- Интеграционные (read-only, реальные базы): `1C_8.1` (517 таблиц; «Банки» — 1141
  запись), `1C_8.3` (8033 таблицы, camelCase; только каталог/схема).
- Пропуск через `pytest.skip`, если базы недоступны.

## Риски

- Неоднозначности FAT-навигации (level 0/1) — уточняются спайком на `1C_8.1`.
- 8.3-хранилище конфигурации (CONFIGCAS/DEPOTFILES/ConfigDumpInfo) — вне этой фазы:
  читаем только каталог таблиц и DBSCHEMA приёмника (структуру), не конфигурацию.
- Большие таблицы (2–3 ГБ): чтение потоковое, по цепочкам, без загрузки целиком.

## Критерий готовности

- `pytest` зелёные: unit (фикстуры) + интеграционные на `1C_8.1` (метаданные «Банки»
  + 1141 запись декодированы) и `1C_8.3` (структура).
- ruff/mypy clean; `read_metadata()` возвращает непустую модель для обеих баз.

# Proposal — фаза-13-zero-setup

**Goal:** Реализовать Фазу 13 «Zero-setup: прямая загрузка в 1CD» (вариант A из docs/zero-setup.md): загрузка данных в приёмник 8.x БЕЗ HTTP-расширения — напрямую в копию 1Cv8.1CD через готовый writer (Фазы 10–12: write_8x.create_1cd/append_records, fat_level 0/1, LockError). Новый модуль src/onec_converter/load_8x.py: load_direct(target_dir, objects, workdir) — для каждого объекта intermediate (после transform: type «Справочник.X», key, attributes с русскими именами реквизитов, references) найти таблицу приёмника через read_metadata (kind+name → _REFERENCE_n, физические поля), собрать строку (encode_row по типам FieldDef: NVC/NC/N/L/DT/B/RV; _IDRREF 16 байт — префикс из существующих строк таблицы + уникальные 12 байт, _MARKED=0, _CODE/_DESCRIPTION из key/атрибутов), append_records в КОПИЮ приёмника (всегда copy_1cd, оригинал не трогается), возврат пути копии и статистики. Контракт загрузки тот же, что у HTTP-load (те же правила TOON после transform). CLI: `onec-converter load --direct <target-dir> --input <batch.json>` (альтернатива --http). MCP: тул load_direct. Интеграционный тест: transform e2e (7.7→8.3 правила) → load_direct в копию реальной 1C_8.1 → чтение парсером, verify (число объектов/строк). Unit-тесты: object_to_row (все типы полей), _IDRREF уникальность. Документация: docs/zero-setup.md (статус MVP реализован), README, docs/pipeline.md. Только stdlib, Python 3.11+, Windows, реальные базы read-only (запись только в tmp-копии). Ворота: pytest (вкл. integration), mypy strict, ruff, vitest (Orion shield).

# Design — Фаза 19: горизонт данных

## Цель
Расширить прямую запись до полноты переноса: регистры (остатки/обороты),
выровнять HTTP-приёмник (replace, документы), честно задокументировать
ограничения (пустые таблицы, 1Cv8.dt). Авторский код.

## Что выяснено (из кода)
- `read_metadata` уже распознаёт регистры (kinds РегистрСведений/Накопления/
  ПланСчетов через `_COLLECTION_CLASS`); физически это обычные таблицы с
  `row_length` → `load_direct` может их записывать (измерения/ресурсы кодируются
  как поля). Подтверждено e2e-тестом `test_load_8x_registers.py`.
- Реальные базы не имеют таблиц с `data_page=0` (все имеют объект данных).
  Пустые таблицы — только у вновь создаваемых приёмников; запись в них
  требует создание объекта данных + обновление каталога `{Files,...}` —
  осознанное ограничение (документировано), реализация сложна/рискованна.
- 1Cv8.dt: проприетарный контейнер, разбор не реализован — осознанный отказ.

## Реализация
1. **Регистры**: запись через существующий load_direct (не требует нового кода);
   e2e-тест фиксирует поведение; документация в format-8x.md.
2. **Module.bsl**: `replace` (поиск по `Код`/`Наименование` → обновить, Обновлено++),
   поддержка `Документ.*`, метаданные включают Документы. (BSL — код-референс.)
3. **Пустые таблицы / 1Cv8.dt**: документирование ограничений.

## Модули

- `tests/test_load_8x_registers.py` (e2e регистр),

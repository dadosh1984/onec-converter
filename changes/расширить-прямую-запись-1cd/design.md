# Design — расширение прямой записи на ссылки и табличные части (Фаза 15)

## Цель

Расширить `load_8x.load_direct` (zero-setup А, Фаза 13) со справочников на
документы со **ссылками (REF-поля)** и **табличными частями (_VT-таблицы)**.
Запись безопасна: `append_records` умеет дописывать строки в fat-объекты.
Ограничение Фазы 14 (индексы не пересобираются) сохраняется и честно
документируется для VT-таблиц.

## Факты формата (из дампов реальной 8.1)

- **REF-поля** базовой строки: `_FLD...RREF` (тип B16), plus служебные
  `_PARENTIDRREF`, `_OWNERIDRREF`, `_OWNERID_RRREF` и т.п. Empty ref = 16 нулей.
- **Документ** — базовая таблица `_DOCUMENTN` с полями `_IDRREF`, `_VERSION`,
  `_MARKED`, `_DATE_TIME`, `_NUMBERPREFIX`, `_NUMBER`, `_POSTED`, затем реквизиты.
  (`_DOCUMENT3190` — 20 полей, напр. `_FLD3192RREF`, …).
- **Табличная часть (VT)** — таблица `_<Base>_VT<num>`, первые поля:
  `_<Base>IDRREF` (16б — _IDRREF базовой строки), `_KEYFIELD` (4б, обычно 0),
  `_LINENO<num>` (порядковый номер строки), далее реквизиты строки
  (напр. `_FLD705`, `_FLD709RREF`). Реал: `_DOCUMENT41_VT770` — 14463 строки.
- `read_metadata` возвращает `objects[].attributes` с `field` (физ. поле),
  `type` (`ref` для B16/RV и др.), и для RL-положений: map `_SYSTEM_FIELDS`
  даёт русские имена только служебным, `_FLD...RREF` остаются как есть.
- `references` в target-объекте после transform — `{имя: "Тип:ключ1|ключ2"}`,
  где `имя` — имя ref-реквизита из правила (русское или `_FLD...RREF`).

## Подход

### REF-резолв приёмника
- Построить индекс `(таблица_приёмника, кортеж_ключей) → _IDRREF` из
  существующих строк базы (по `_CODE`, `_DESCRIPTION` / ключу объекта).
- Для каждого REF-поля строки: значение берём из `references` по имени поля.
  Формат значения — `"Тип:ключ1|ключ2"` (как в transform). Тип мапим в таблицу
  приёмника через `read_dbnames` (kind→префикс, номер из имени), ключ — в
  `_IDRREF` через индекс. Ненайденный ключ/тип → **16 нулей + запись в отчёт**
  `errors`/`warnings` (не прерываем пакет).
- Пустой ref (пустое значение / нет в references) → 16 нулей (валидно).

### Табличные части (VT)
- Расширяем `object_to_row`/`load_direct`: объект после transform может нести
  опциональный ключ `tab_sections` (`{имя_ТЧ: [строки…]}`) или объект уже
  разбит на «базовую строку + VT-строки». Выбираем модель: в `objects` каждая
  ТЧ-строка — отдельный объект `{'type': 'ТабличнаяЧасть.<Документ>.<ИмяТЧ>',
  'parent': idref_базы(или ключ базы), 'line': N, 'attributes': {...}}`.
- `load_direct` пишет базовые строки, затем для каждой VT-строки находит
  `_<Base>IDRREF` (parent idref базовой строки этого документа) и пишет её.
  `_LINENO` = порядковый номер. `_KEYFIELD` = 0.
- Индексация VT-таблиц не пересобирается (UserWarning append) — задокументировать.

### Документы: реквизиты базовой строки
- `_NUMBER` из `key[0]` (номер) или атрибута; `_DATE_TIME`/`_POSTED`/`_NUMBERPREFIX`
  — из атрибутов `Дата`/`Проведён`/`Префикс` или нули; задокументировать.

## Модули

- `src/onec_converter/load_8x.py` — REF-резолв (индекс приёмника), VT-запись.
- `src/onec_converter/source_8x_file.py` — (при необходимости) helper построения
  индекса `таблица→(ключ→_IDRREF)`; вспомогательное, не ломая API.
- `tests/test_load_8x_refs.py` — unit-тесты REF, VT, missing-ref.
- `tests/test_load_8x_doc_e2e.py` — e2e: документ со ссылками и ТЧ → парсер читает.
- `docs/format-8x.md` — раздел «Ссылки и табличные части (Фаза 15)».
- `README.md` — снять ограничения MVP по ссылкам/ТЧ; оставить по индексам ВТ.

## Ограничения / риски
- Запись только на копиях (LockError остаётся).
- Индексы (в т.ч. VT) не пересобираются — Фаза 14.
- `_DATE_TIME`/`_POSTED`/`_NUMBERPREFIX` при неявной передаче — нули/дефолт.
- Ненайденные REF — нули + отчёт, не ошибка пакета.
- Не меняем public-поведение существующих справочников (append без ref работает).

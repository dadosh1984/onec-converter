# Spec: pytest_mypy_strict_ruff_vitest_orion_thi

## Назначение
Добавить в bridge-migrate фазу сравнения метаданных источника и приёмника по user-объектам (шаги 5-6 алгоритма переноса): для каждого user-объекта (Справочник/Документ/РегистрСведений по классификации user/formula/service) сравнить структуру в источнике и в копии приёмника — состав реквизитов (имя+тип+длина) и наличие таблиц (включая VT-таблицы документов). Несовпадение метаданных означает, что перенос раздела не может быть корректным — такой раздел исключается из плана, а расхождение попадает в отчёт-список с пояснением (какой реквизит/таблица отличается). Результат — два списка для пользователя: 'ok' (разделы, готовые к переносу) и 'conflict' (разделы с расхождением структуры + детали). CLI-флаг bridge-migrate '--meta-conflicts' для вывода отчёта без запуска переноса. Функция compare_user_metadata(source_meta, target_meta) в new модуль (или в classify.py): возвращает {'ok': [...], 'conflict': [{'name', 'kind', 'diff': [...]}]}.

## Область

- В области: указанная возможность, поставляется тест-первой.
- Вне области: всё, что не заявлено в предложении.

# Proposal — фаза-10-прямая-запись

**Goal:** Фаза 10: прямая запись в 1CD 8.3 для onec_converter (перенос данных между ИБ 1С) — загрузка в приёмник 8.x без HTTP-расширения. Сейчас есть read-only парсер source_8x_file (Database1CD: заголовок, каталог, таблицы, FAT level 0/1, цепочки блоков, BINARYDATA, SERIALIZEDDATA) и фикстуры fake_1cd (FixtureTable/FixtureField/write_fake_1cd). Задачи: (1) [spike] формат 1CD 8.3 на запись — что нужно для создания новой базы / добавления записей в существующую (root-объект, каталог таблиц, FAT level 0/1, цепочки блоков, SERIALIZEDDATA, обновление размеров); риски целостности; зафиксировать в docs/format-8x.md раздел «Запись»; (2) [assumption] write_8x.py: создание новой пустой базы 1CD по структуре приёмника (таблицы, поля, индексы); (3) [assumption] вставка записей в существующие таблицы: добавление строк в конец, обновление размера таблицы и FAT; (4) [fact] unit-тесты: созданная база читается собственным парсером; записанные строки декодируются обратно без потерь; (5) [assumption] интеграционный тест на КОПИИ 8.3-базы (tmp): копия исходника → запись тестовых записей → чтение парсером; (6) [assumption] README/docs: документация формата записи + ограничения (только копии, не оригиналы). Ворота: pytest, mypy strict, ruff, vitest (.ts-сниппеты для Orion). Python 3.11+, Windows, реальные базы read-only. Авторский код с нуля; работаем только на копиях; mypy strict/ruff/pytest зелёные; без новых зависимостей. — Модуль записи не должен дублировать логику чтения — переиспользовать Database1CD/fake_1cd (структура таблиц, поля, форматы)

- Platform: Только stdlib для записи; работа только с копиями баз (не оригиналами); ворота pytest/mypy strict/ruff/vitest зелёные.

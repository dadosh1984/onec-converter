# Исследование .epf «ЗагрузкаДанныхИзТабличногоДокумента_УФ_v2» и схема алгоритма

## 1. Бинарный формат .epf (контейнер 1С 8.x)

Файл — НЕ ZIP, а собственный контейнер 1С 8.0–8.2. Структура (разобрана
эмпирически, полный парсер: `epf_extracted/` + скрипты в истории):

```
0x00:  сигнатура 0x7FFFFFFF (4 байта)
0x04:  версия = 2 (4 байта)
0x08:  счётчик файлов N = 22 (4 байта)
0x0C:  нули (4 байта)
0x10:  текстовый заголовок корня: "\r\n00000108 00000200 7fffffff \r\n"
       (0x108 = размер таблицы индекса = 22×12)
0x2F:  индекс: N записей по 12 байт: [offset 4B][end 4B][0x7FFFFFFF 4B]
0x137: 8 нулевых байт (конец индекса)
далее: блоки данных
```

**Блок-узел каталога** (небольшой, 63–131 байт):
```
"\r\n%08x %08x 7fffffff \r\n"  — где %08x = размер payload
payload: 20 байт бинарных ссылок + имя (UTF-16LE) + 4 нулевых байта
имя = GUID файла или служебное: root / version / versions / copyinfo
```

**Блок данных** (между узлами): `"\r\n%08x %08x 7fffffff \r\n"` +
**raw-deflate** поток (zlib, wbits=-15); %08x = размер распакованных данных.
Содержимое — текстовый поток 1С: BOM + `{1,{0,{12,{1,...` (формат "InternalFormat").

## 2. Состав файлов внутри .epf (22 файла)

| Файл | Роль |
|---|---|
| `root` | `{2,<GUID главной формы>,}` — точка входа |
| `version`, `versions`, `copyinfo` | версии, история файлов (UUID→имя) |
| `<GUID>` (00,03,05,07,09,12,14,17) | краткое описание формы (имя, заголовок) |
| `<GUID>.0` (01,02,04,06,08,10,13,15,18) | **полная форма**: структура + модуль (код 1С в одной строке, кавычки удвоены `""`, конец — `"` перед `,`) |
| `11` | главная форма «ЗагрузкаДанныхИзТабличногоДокумента» |

Модули извлечены в `epf_extracted/modules/`. Главный — `10_...` (2946 строк,
110 процедур). Остальные — вспомогательные формы: редактирование событий
(01), редактор выражений, список связей по типу/владельцу (04, 13, 15, 18).

## 3. Схема алгоритма (по главному модулю)

### 3.1 Режимы загрузки (Объект.РежимЗагрузки)
- **0 — в справочник**: создание/обновление элементов справочника.
- **1 — в табличную часть**: добавление строк в ТЧ объекта (документ/справочник).
- **2 — в регистр сведений**: запись наборов записей (измерения = колонки с признаком поиска).

### 3.2 Данные и маппинг
- Данные — «ТабличныйДокумент» (xlsx): шапка в строке 1, данные с
  `ПерваяСтрокаДанныхТабличногоДокумента` (настраивается).
- Маппинг — таблица реквизитов (ТаблицаЗагружаемыхРеквизитов). На колонку:
  `Пометка`, `ИмяРеквизита`, `ПолеПоиска`, `ОписаниеТипов`, `РежимЗагрузки`
  (Устанавливать/Вычислять), `ЗначениеПоУмолчанию`, `ИскатьПо`, `СвязьПоВладельцу`,
  `СвязьПоТипу`, `ЭлементСвязиПоТипу`, `НомерКолонки`, `Выражение`.

### 3.3 Чтение xlsx (мПрочитатьТабличныйДокументИзExcel)
Через COM `Excel.Application`: лист → сетка (текст ячеек `Cells.Text`) → ТабличныйДокумент.
Также поддержаны TXT (таб-разделитель) и DBF.

### 3.4 Контроль строки (КонтрольЗаполненияСтроки) — построение значения
Для каждой активной колонки:
1. **Устанавливать** → значение по умолчанию.
2. **Вычислять** → `Выполнить(<Выражение>)` — код 1С (клиент-независимо), с ТекущиеДанные/ТекстЯчейки.
3. Иначе `ОбработатьОбласть` → `ПолучитьВозможныеЗначения(Колонка, ТекстЯчейки)`:
   - **Число/Булево**: `мПривестиКЧислу` — «да/истина/включено»→1, «нет/ложь/выключено»→0,
     пробелы убраны, проверка по квалификаторам (длина/разрядность/знак).
   - **Строка**: как есть; **Дата**: `мПривестиКДате` — парсинг ДД.ММ.ГГГГ ЧЧ:ММ:СС,
     авто-век века (<30→2000+), перестановка день/год если год ≥ 1000; части даты по квалификатору.
   - **Перечисление**: сравнение представлений.
   - **Документ**: разбор «Номер от ДД.ММ.ГГГГ» → `НайтиПоНомеру(Номер, Дата)`.
   - **Справочник/др.**: запрос `ВЫБРАТЬ Ссылка ГДЕ <ИскатьПо> = &Представление`
     (ИскатьПо по умолчанию = основное представление: Код/Наименование/Номер);
     + `И Владелец = &СвязьПоВладельцу` (если задан, и у типа есть владельцы);
     + `СвязьПоТипу` для видов субконто (ЭлементСвязиПоТипу).
   - Результат: 0 найденных → ошибка «Не найден», >1 → «Не однозначное представление»
     (берётся значение по умолчанию или первое), 1 → оно.
   - Пустое значение → значение по умолчанию.

### 3.5 Поиск/создание объекта
- **Справочник (0)**: по колонкам с `ПолеПоиска` строится запрос
  `ВЫБРАТЬ ПЕРВЫЕ 1 ... ГДЕ <поле> = &<поле> И ...`. Найдено → обновлять (только отмеченные
  колонки), не найдено → `СоздатьЭлемент()` (если не включено «Не создавать новых элементов»).
- **ТЧ (1)**: `Источник.Очистить()` затем для каждой строки `Источник.Добавить()`,
  в конце запись родительского объекта.
- **Регистр (2)**: `СоздатьМенеджерЗаписи()`, измерения из колонок поиска,
  `Прочитать()` → если запись есть и не «Замещать» → пропуск/обновление.

### 3.6 Запись (ЗаписатьОбъект) — транзакция + события
```
НачатьТранзакцию
если ПередЗаписьюОбъекта <> "" → Выполнить(код)   (Отказ прерывает)
Объект.Записать()
если ПриЗаписиОбъекта <> "" → Выполнить(код); Объект.Записать() снова
ЗафиксироватьТранзакцию / при ошибке ОтменитьТранзакцию
```
ОбменДанными.Загрузка = Истина для справочников/документов. События — произвольный код 1С,
задаваемый пользователем (для ТЧ также «ПослеДобавленияСтроки»).

## 4. Формат xlsx-моста (макет «МакетСохраненияНастроек»)

Файл настроек — тот же ТабличныйДокумент (mxl/xlsx), строки:
```
R1C5 (v1.2) / R1C5(1.1): "1.2" / "1.1"            — версия
R2C5 (v1.2) / R1C5(1.1): "в справочник"/"в табличную часть"/"в регистр сведений"
R3C5 (v1.2) / R2C5(1.1): полное имя объекта (Справочник.Контрагенты, ...)
R4–R8: флаги НеСоздаватьНовых / ЗамещатьСуществующие / РучнаяНумерация / ПерваяСтрока
данные с R11 (v1.2) / R9 (v1.1), колонки:
 C1=Пометка(Х)  C2=ИмяРеквизита  C3=ПолеПоиска(Х)  C4=ОписаниеТипов
 C5=РежимЗагрузки  C6=ЗначениеПоУмолчанию  C7=ИскатьПо|Выражение
 C8=СвязьПоВладельцу  C9=СвязьПоТипу  C10=ЭлементСвязиПоТипу  C11=НомерКолонки
подвал: ПередЗаписьюОбъекта / ПриЗаписиОбъекта / ПослеДобавленияСтроки (код 1С)
```
**Формат описания типов (C4)**: строка,число,булево,дата,время,дата и время
(с квалификаторами: `строка,20,0`, `число,15,2`, `число,10,0,0` — знак),
`Справочник.Имя` / `Документ.Имя` / `Перечисление.Имя` (точка → «Ссылка.»).
Значения по умолчанию/связи — `ЗначениеВСтрокуВнутр` (формат `{...}`).

## 5. Архитектура Python-реализации (Фаза 2 — дизайн)

База: проект **onec_converter** (E:\SYSTEM\Desktop\AI_Projects\onec_converter) — уже
умеет читать 1Cv8.1CD (source_8x_file) и 1Cv7 (v77_reader), писать в 8.x напрямую
(load_8x/write_8x, работа только на КОПИЯХ баз), резолвить ссылки по естественным
ключам (resolver.RefResolver), открывать xlsx (openpyxl). Новый код — модули
пакета `onec_converter` по образцу существующих, с тестами в E:\test.

### 5.1 Новые модули

| Модуль | Назначение | Аналог в epf |
|---|---|---|
| `bridge_format.py` | формат xlsx-моста: парсинг/запись шапки (версия, режим, объект, флаги), таблицы маппинга C1–C11, подвала (события) | МакетСохраненияНастроек (v1.1/v1.2) |
| `typify.py` | текст ячейки → значение по описанию типов | мПривестиКЧислу/мПривестиКДате/ПолучитьВозможныеЗначения |

### 5.2 Формат xlsx-моста (совместим с макетом epf)

Один файл `bridge.xlsx`, два листа:
- **Настройки** — шапка (R1C1=версия «1.2», R2C1=режим «в справочник»/«в табличную часть»/«в регистр сведений», R3C1=полное имя объекта, R4–R6=флаги, R7=первая строка данных) + строки маппинга с C1=Пометка, C2=ИмяРеквизита, C3=ПолеПоиска, C4=ОписаниеТипов, C5=РежимЗагрузки, C6=ЗначениеПоУмолчанию, C7=ИскатьПо/Выражение, C8=СвязьПоВладельцу, C9=СвязьПоТипу, C10=ЭлементСвязиПоТипу, C11=НомерКолонки (1:1 со схемой §4) + подвал с событиями-хуками (Python-выражения вместо кода 1С).
- **Данные** — R1=заголовки (представления реквизитов, по НомерКолонки), строки данных от ПерваяСтрокаДанных.

Формат описания типов (C4) — как в epf: `строка[,N[,0]]`, `число,разрядность,точность[,0]`,
`булево`, `дата`/`время`/`дата и время`, `Справочник.Имя`/`Документ.Имя`/`Перечисление.Имя`.

### 5.3 Потоки

**ИБ-источник → xlsx** (`bridge export`): источник (8.x/7.7) + JSON-конфиг маппинга
→ типизация значений → ссылки как представления (Код/Наименование, «Номер от Дата»)
→ xlsx-мост. Заменяет ручной макет настроек epf.

**xlsx → ИБ приёмник** (`bridge import`): xlsx-мост → типизатор (да/истина→1, даты с
авто-веком, числа без пробелов) → резолвер ссылок (ИскатьПо + владелец, против индекса
приёмника) → find-or-create:
- режим 0 (справочник): по колонкам ПолеПоиска ищем существующую запись в приёмнике
  (индекс по полю поиска); найдена → перезапись отмеченных колонок через
  `update_record`; не найдена → добавление (если не «не создавать новых»);
- режим 1 (ТЧ): find-or-create объекта-владельца, строки в его VT-таблицу;
- режим 2 (регистр сведений): измерения = колонки поиска; запись есть и не
  «замещать» → пропуск, иначе перезапись/добавление.

Транзакции на строку (snapshot приёмника — уже в load_direct), события «Перед/При
записи» — Python-хуки (функции из конфига; код 1С `Выполнить` не переносим —
документируется как ограничение).

### 5.4 Ограничения
- Код-события 1С (Перед/ПриЗаписиОбъекта) → Python-хуки, не 1:1.
- «Вычислять»-выражения epf — код 1С; в Python — ограниченный eval (sandbox, без импорта) или JSONata.
- Запись только в копию приёмника (правило onec_converter, оригинал не меняем).

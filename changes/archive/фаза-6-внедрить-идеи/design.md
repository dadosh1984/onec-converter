# Design — фаза-6-внедрить-идеи

## Overview

Фаза 6: внедрение идей внешних 1С-проектов (изучены 200 проектов из
`github_list.xlsx` + ранее изученные парсеры tool1cd/onec_dtools).
Принцип проекта: берём ТОЛЬКО идею, усовершенствуем, реализуем авторским
кодом (никаких сторонних библиотек 1С). Результат — 12 идей, сгруппированных
в 4 трека. Источник каждой идеи фиксируется в `docs/ideas.md`.

## Треки

### Трек A — парсер и данные (`source_8x_file.py`)
1. **Кеш ссылок GUID→наименование** (идея: tool1cd/onec_dtools «кеш ссылок»):
   `read_table(..., resolve_refs=True)` — REF-поля (RV/B) отдаются как
   `{guid, name}` через кеш имён из `_ReferenceNN`/`_DocumentNN` (lazy, по
   ключу blob_page+IDRREF, в памяти процесса). Имя берётся из описания
   («Наименование» и т.п.) либо из первого строкового поля.
2. **Размеры таблиц в status** (идея: 1C_PrometheusExporter / ClusterMonitoring —
   метрики): `status`-тул MCP дополняется `table_sizes`: для каждой таблицы —
   число строк и объём данных (вычисляется при первом запросе, кешируется).
   + **журнал метрик времени** по типам объектов (histogram выгрузки:
   read_metadata/read_table по типу, ms) — лёгкий `Timings`-лог в memory.
3. **CP1251→UTF-8 middleware** (идея: кодировки в 7.7-источниках): слой
   перекодирования текстовых полей 7.7 (CP1251) → UTF-8 на стыке чтения
   строк/реквизитов; параметр коннектора `encoding` (cp1251 по умолчанию
   для 7.7, utf-8 для 8.x).
4. **Генератор синтетической мини-1CD** (идея: 1C-Company/dt-demo-configuration —
   демо-базы для тестов): функция `build_fake_1cd(path, tables, rows)` —
   создаёт валидную маленькую файловую базу (заголовок, root-объект,
   blob-таблицы, строки) для unit-тестов без реальных 2.5-ГБ баз.

### Трек B — конвертация (`mapping_rules.py`, `transform.py`)
5. **TYPE_PRIORITY** (идея: 1cdtools «TYPE_PRIORITY»): детерминированный
   порядок типов при конвертации полей — Str < Num < Date < Bool < Ref
   (адаптация `_DBNAME_PRIORITY` из Фазы 5): `resolve_type_priority(types)`
   выбирает целевой тип при неоднозначности.
6. **TOON — таблица соответствий** (идея: Конвертация данных 3, TOON):
   JSON-правила маппинга «объект/реквизит источника → приёмника»
   (`mapping_rules.json`), замена жёстких маппингов в коде; валидация правил,
   применение в `transform.py`.
7. **Импорт правил обмена КД3** (идея: otymko/gitrules — разбор XML правил
   конвертации/регистрации): парсер XML правил обмена «Конвертации данных 3»
   (форматы `Rules/` конфигурации КД3) → JSON-правила TOON.
8. **Анонимизатор PII** (идея: маскирование персональных данных):
   `anonymizer.py` — маскировка ФИО/телефонов/ИНН по маске (regexp) или
   списку реквизитов при выгрузке; параметр пайплайна `anonymize: {...}`.

### Трек C — MCP-интерфейс (`mcp_server.py`)
9. **MCP-тул поиска метаданные↔таблицы** (идея: alexkmbk/1CDBStorageStructureInfo —
   двунаправленный поиск): тул `search_schema(query)` — ищет по имени
   метаданных («Номенклатура») и по имени таблицы/поля («REFERENCE106»),
   возвращает совпадения с типами.
10. **Diff-отчёт структур** (идея: RDT1C «Инструменты разработчика» — анализ
    конфигураций): тул `compare_structures(source, target)` — объекты/поля
    только в источнике / только в приёмнике / различающиеся типы; XLSX-отчёт.
11. **Консоль запросов** (идея: RequestConsole9000 / consquery — консоль
    запросов): тул `query_table(table, filters, limit)` — выборка записей
    `read_table` с фильтром по условиям на поля (`field op value`).

### Трек D — инфраструктура и документация
12. **Экспорт метаданных в git-дружественный текст** (идея: 1C-Company/GitConverter):
    `dump_metadata(path, fmt=yaml|json)` — выгрузка метаданных базы
    (объекты/таблицы/поля) в YAML/JSON для git-диффов; CLI-команда.
13. **docs/ideas.md** — список всех идей с обоснованием и источником
    (обязательный артефакт фазы).

## Порядок реализации

A(4 генератор → 1 кеш → 2 метрики → 3 middleware) → B(5,6,7,8) →
C(9,10,11) → D(12,13). Каждая идея: RED (unit-тест на синтетике/фикстуре) →
GREEN → REFACTOR. Интеграционные проверки на реальных базах 1C_8.1/1C_8.3
(read-only) там, где уместно.

# Design — mcp-python-1-7

## Overview

Кроссплатформенный MCP-сервер на **Python 3.11+** для переноса данных из информационных баз
1С:Предприятие **7.7 / 8.1 / 8.2 / 8.3** в информационные базы **1С:Предприятие 8.3**
по командам LLM-агентов (Claude, Cursor).

Сервер работает **без установленной платформы 1С** и не требует Windows (кроссплатформенный).

Проект — **авторский, пишется с нуля** (см. Philosophy). Чужие проекты сообщества
(tool1cd, onec_dtools, 1creader и др.) изучаются как источник знаний о внутренних форматах,
из них берутся **только идеи/логика**, код пишется свой с улучшением качества,
скорости и производительности.

## Philosophy (правила проекта)

1. **Авторский код.** Ни одна сторонняя библиотека/программа в проект не включается.
   Чужие проекты — только для изучения форматов и идей (документируется, что именно изучено).
2. **Одна передающая ИБ → одна принимающая ИБ.** Смешивать данные разных источников
   в одном приёмнике ЗАПРЕЩЕНО. Проект переноса привязывается к паре
   (источник, приёмник) и хранит эту привязку; загрузка в приёмник блокируется,
   если контекст другого источника не совпадает.
3. **100% верификация.** Каждый перенос завершается проверкой полноты и корректности:
   количество записей, контрольные суммы, сверка «источник ↔ приёмник».
   Сначала убеждаемся, что данные найдены правильно, потом — что перенесены полностью.
4. **Скорость через кеш.** ИБ достигают 2–3 ГБ. Метаданные и разобранные данные
   кешируются; повторный анализ базы не перечитывает её целиком.
5. Остальные характеристики уточняются по мере разработки.

## Pipeline (алгоритм сервера)

Последовательность шагов-команд, применяемая к запросу пользователя.
Точный состав финализируется в ходе разработки (Фаза 6); ниже — рабочая схема:

```
init → inspect_source → extract → inspect_target → map
     → transform → prevalidate → preview → load → verify
```

1. `init` — привязка проекта к паре ИБ (источник + приёмник), правило «1→1»;
   проверка доступности, идентификаторов, кеша.
2. `inspect_source` — метаданные источника из кеша или из парсинга
   (7.7: `1Cv7.MD`+`1Cv77.dat`; 8.x: `1Cv8.1CD`) → единая модель.
3. `extract` — потоковое чтение данных → промежуточный формат
   (XML/JSON машинный + xlsx человекочитаемый) + **статистика/срезы для верификации**.
4. `inspect_target` — структура приёмника 8.3: чтение `1Cv8.1CD` напрямую
   и/или `/metadata` HTTP-сервиса расширения.
5. `map` — LLM строит правила сопоставления (JSON): объект→объект, реквизит→реквизит,
   перечисления; ссылки переназначаются по естественным ключам (код+наименование).
6. `transform` — конвертация данных по правилам.
7. `prevalidate` — контроль: количество, целостность ссылок, дубликаты, конфликты ключей,
   несоответствие типов; отчёт xlsx для человека.
8. `preview` (dry-run) — пробная загрузка в приёмник без фиксации
   (или расчёт контрольных сумм) — подтверждение перед реальной записью.
9. `load` — пакетная запись в 8.3 через HTTP-сервис расширения (`/load`).
10. `verify` — **финальная верификация**: сверка «источник ↔ приёмник»
    по количеству, контрольным суммам, реестру перенесённых объектов;
    отчёт о 100% полноте или списке расхождений.

### Кеширование

- **Кеш метаданных** — результат парсинга конфигурации источника (дерево объектов,
  реквизиты, типы, привязка таблиц) сериализуется один раз; при повторном обращении
  читается мгновенно.
- **Кеш данных** — промежуточный формат (extract) сам является кешем данных:
  повторный map/transform/load не перечитывает базу.
- **Ключ кеша** — контрольная сумма признаков: путь, размер файла, mtime,
  хэш заголовка/страниц каталога таблиц; изменение базы → инвалидация.
- **Хранилище** — каталог проекта (`.onec_cache/<hash>/`), компактные форматы
  (JSON/gzip/специфичный бинарный), размеры фиксируются в отчёте.
- **Идемпотентность** — повторный extract/load не дублирует данные
  (ключ «источник+объект+внутр. ID» в журнале переноса).

## Universality — универсальность по источникам

Перенос возможен **из любой версии 1С** (7.7, 8.1, 8.2, 8.3) **в любую 8.x**.
Конвейер и внутренняя модель версионно-независимы; коннекторы источников и приёмников
симметричны. Основной сценарий: любой источник → **приёмник 8.3**. Приёмник 8.1/8.2 —
возможен (веб-/HTTP-сервисы); **приёмник 7.7 не поддерживается** (нет механизма
расширений; приоритет — миграция со старых платформ на новые).

Коннекторы источников нормализуют данные в **единую внутреннюю модель**
(объекты, реквизиты, ссылки по естественным ключам); конвейер map/transform/validate/load
работает только с моделью и не зависит от формата источника.

| Версия | Формат источника | Коннектор | Статус |
|---|---|---|---|
| 7.7 | каталог ИБ (`1Cv7.MD` + `1Cv77.dat`) | `v77_reader` | MVP, спайк подтверждён |
| 7.7 | `1Cv7.DT` (zlib) | `base_reader` | опционально |
| 8.1/8.2/8.3 | `1Cv8.1CD` (файловая ИБ) | `source_8x_file` | **основной для 8.x** — собственный парсер 1CD (логика формата изучена у сообщества; спайк подтверждён на реальной базе: 1CD 8.3.8.0, 517 таблиц) |
| 8.x | `1Cv8.dt` (выгрузка) | `source_8x_dt` | запасной; проприетарный формат дампа, не исследован |
| 8.x | серверная ИБ (MS SQL / PostgreSQL) | `source_sql` | опционально, нужны доступы |
| 8.3 | HTTP-сервис (тот же контракт, что приёмник) | `source_http` | опционально — единый механизм чтения/записи |

Замечания:
- Структуры `.1CD` различаются между поколениями платформы; подтверждён формат 8.3.8.0,
  именование таблиц: 8.1-эпоха — `_REFERENCE3`, 8.3 — `_Reference74` (оба стиля поддерживаются).
- Приёмник всегда 8.3 (расширение с HTTP-сервисом).

## Целевой сценарий (реальные базы)

- Источники: `1С_7.7` (учёт, банки Узбекистана) и `1C_8.1` (Банки РУз, 1141 запись).
- Приёмник: `1C_8.3` — конфигурация **«Бухгалтерия для Узбекистана, редакция 3.0»**,
  данных нет. Правило «1→1»: каждая пара источник→приёмник — отдельный проект переноса.

## Modules

```
src/onec_converter/
├── base_reader.py      # вход: каталог ИБ 7.7 (1Cv7.MD + 1Cv77.dat) или архив 1Cv7.DT
│                       #   распаковка .dt (zlib) — опциональный коннектор
├── v77_metadata.py     # парсер 1Cv7.MD (OLE2-контейнер, olefile): дерево объектов,
│                       #   реквизиты, типы, перечисления, точность чисел
├── v77_reader.py       # парсер 1Cv77.dat (текстовый формат, CP866→UTF-8): секции,
│                       #   ID-ссылки "NNN|", даты YYYYMMDD, числа
├── source_8x_file.py   # СВОЙ парсер 1Cv8.1CD: заголовок, страницы, таблицы, строки,
│                       #   blob; конфигурация (дерево объектов, имена);
│                       #   привязка таблица↔объект (порядок коллекции + DBSCHEMA)
├── source_8x_dt.py     # чтение 1Cv8.dt (выгрузка 8.x) — опционально
├── source_sql.py       # чтение серверных ИБ (MS SQL / PostgreSQL) — опционально
├── source_http.py      # чтение ИБ 8.3 через HTTP-сервис — опционально
├── model.py            # единая внутренняя модель (объекты, реквизиты, ссылки)
├── intermediate.py     # промежуточный формат XML/JSON + xlsx-отчёт (openpyxl)
├── cache.py            # кеш метаданных/данных: ключ, инвалидация, хранилище
├── mapping.py          # JSON-схема правил, резолвер ссылок по естественным ключам, коллизии
├── transform.py        # применение правил к данным
├── validate.py         # количество, целостность ссылок, дубликаты; verify-отчёт
├── http_client.py      # асинхронный httpx-клиент HTTP-сервиса 8.3 (пакеты, retry, таймауты)
├── mcp_server.py       # MCP-сервер: тулы пайплайна (init/inspect/extract/map/transform/.../verify)
└── extension_83/       # исходники расширения конфигурации 1С 8.3 (XML) + README по установке
                        #   HTTP-сервис: GET /metadata, POST /load
```

## Key decisions

- **Без платформы 1С и без Windows** — сервер читает каталог ИБ (или `.dt`) напрямую.
- **Философия**: авторский код; чужие проекты — только для изучения (документируется в docs/).
- **Правило «1→1»**: одна передающая ИБ = одна принимающая ИБ; контекст проекта хранится
  и проверяется перед загрузкой.
- **Источник 7.7** — каталог файловой ИБ в текстовом формате:
  `1Cv7.MD` (метаданные, OLE2-контейнер) + `1Cv77.dat` (данные: JSON-подобный текст,
  CP866). Опционально — архив `1Cv7.DT` (zlib). Формат подтверждён на реальной базе
  (см. `docs/format-77.md`); внутренний формат `1Cv7.MD` дорабатывается в спайке.
- **Источник 8.x** — файловая ИБ `1Cv8.1CD`: **собственный парсер** (логика формата
  изучена у tool1cd/onec_dtools/1creader; подтверждена на реальных базах 8.1-эпохи и 8.3,
  см. `docs/format-8x.md`). Кодировка данных — UTF-16LE/UTF-8.
- **Приёмник (MVP)** — расширение 1С 8.3 с HTTP-сервисом: `/metadata` отдаёт структуру,
  `/load` принимает данные и создаёт объекты (в т.ч. табличные части). Структура приёмника
  читается также напрямую из `1Cv8.1CD` приёмника. Расширение собирается пользователем
  в 1С:Предприятие (Designer), исходники поставляются в репозитории.
- **Приёмник (целевая фича, roadmap)** — «zero-setup»: минимальное вмешательство пользователя
  (не все умеют работать с расширениями 1С). Варианты: автоустановка/подключение расширения
  через `1cv8.exe DESIGNER` при наличии платформы; **прямая запись в `1Cv8.1CD` приёмника**
  (собственный writer — формат уже разобран парсером; требует управления блокировками,
  целостностью, журналом). Решение — на Фазе 4+; расширение остаётся fallback.
- **Ссылки** — перенос по естественным ключам (код/наименование) с разрешением коллизий;
  GUID не совпадают между базами.
- **Промежуточный формат** — XML/JSON (машинный) + xlsx (человеческая верификация).
- **Верификация** — обязательный этап `verify`: сверка полноты «источник ↔ приёмник»
  по количеству и контрольным суммам; отчёт с расхождениями.
- **Кеш** — метаданные и данные кешируются (ключ: путь+размер+mtime+хэш каталога);
  повторный анализ базы 2–3 ГБ не требует полного перечитывания.
- **Большие объёмы** — потоковая обработка (итераторы по файлам, пакетная запись в 8.3).
- **Тестирование** — синтетические фикстуры: генераторы `1Cv77.dat` и `1Cv8.1CD`;
  реальные базы: `1С_7.7`, `1C_8.1`, `1C_8.3` — интеграционные тесты (копия во временную
  папку, read-only).

## MVP scope

Справочники и документы **без табличных частей**. Далее: табличные части, перечисления,
регистры накопления/сведений, потоковый перенос больших объёмов.

# Spec: mcp-python-1-7

## Purpose
Создать кроссплатформенный MCP-сервер на Python (3.11+) для переноса данных из информационных
баз 1С:Предприятие **7.7 / 8.1 / 8.2 / 8.3** в информационные базы 1С:Предприятие **8.x**
(основной приёмник — **8.3**) по командам LLM-агентов (Claude, Cursor). Конвейер и внутренняя
модель универсальны: любой источник → любой приёмник 8.x; приёмник 7.7 не поддерживается. Сервер работает **без установленной платформы 1С**
(Windows/Linux/macOS).

Проект — **авторский**: код пишется с нуля; чужие проекты сообщества (tool1cd, onec_dtools,
1creader и др.) изучаются только как источник идей/логики внутренних форматов, в проект не включаются.

**Источники**:
- 7.7 — каталог файловой ИБ (`1Cv7.MD` + `1Cv77.dat`, текстовый формат, CP866); опционально `1Cv7.DT`
- 8.1/8.2/8.3 — файловая ИБ `1Cv8.1CD` (собственный парсер; кодировка UTF-16LE/UTF-8)
- опционально: `1Cv8.dt`, серверные БД (SQL), 8.3 через HTTP-сервис

**Приёмник**: база 1С 8.x (основной — 8.3, файловая ИБ `1Cv8.1CD`). Запись (MVP) — через
устанавливаемое расширение конфигурации с HTTP-сервисом (`/metadata`, `/load`);
структура приёмника читается также напрямую из его `1Cv8.1CD`. Целевая фича — «zero-setup»:
прямая запись в `1Cv8.1CD` приёмника собственным writer'ом и/или автоустановка расширения
через `1cv8.exe DESIGNER` — чтобы вмешательство пользователя было минимальным.

**Правило «1→1»**: одна передающая ИБ = одна принимающая ИБ. Смешивание данных разных
источников в одном приёмнике не допускается; проект переноса хранит привязку пары и проверяет её.

**Промежуточный формат**: XML/JSON (машинный) + человекочитаемые xlsx-отчёты для верификации.
**Кеш**: метаданные и данные кешируются (ключ: путь+размер+mtime+хэш каталога таблиц);
повторный анализ ИБ 2–3 ГБ не перечитывает её целиком.
**Верификация**: обязательный финальный этап сверки «источник ↔ приёмник»
(количество, контрольные суммы, реестр перенесённого, отчёт о расхождениях).

**Пайплайн тулов**: init (привязка пары, «1→1») → inspect_source (метаданные источника,
кеш) → extract (данные → промежуточный формат + статистика) → inspect_target (структура 8.3:
`1Cv8.1CD` приёмника и/или `/metadata`) → map (LLM генерирует правила сопоставления объектов,
реквизитов, перечислений; ссылки переназначаются по естественным ключам код/наименование,
т.к. GUID не совпадают) → transform → prevalidate (количество, целостность ссылок, дубликаты,
конфликты) → preview (dry-run перед записью) → load (пакетная запись в 8.3 через HTTP-сервис)
→ verify (финальная сверка полноты).

**Объёмы**: потоковая обработка, устойчивость к большим таблицам (регистры).
**MVP**: справочники и документы без табличных частей; затем табличные части, перечисления,
регистры накопления/сведений.

## Acceptance criteria
- [ ] MCP-сервер запускается на Windows/Linux/macOS без установленной платформы 1С
- [ ] **Авторский код**: в проекте нет сторонних библиотек/кода, включённых из чужих проектов;
      изученные проекты и взятые из них идеи задокументированы в `docs/`
- [ ] Из каталога ИБ 7.7 (`1Cv7.MD` + `1Cv77.dat`) извлекаются метаданные и данные
      справочников и документов (MVP: без табличных частей); формат подтверждён на реальной базе
- [ ] Из `1Cv8.1CD` (8.1-эпоха и 8.3) читаются таблицы, строки, имена объектов, привязка
      таблица↔объект; подтверждено на реальных базах
- [ ] Генерируются промежуточные XML/JSON и человекочитаемый xlsx-отчёт
- [ ] Правила маппинга задаются JSON-схемой; LLM генерирует их по метаданным обеих сторон
- [ ] Ссылки переносятся по естественным ключам (код/наименование), коллизии обрабатываются
- [ ] Валидация ловит несоответствие количества, битые ссылки и дубликаты
- [ ] Данные загружаются в 8.3 через HTTP-сервис расширения пакетами, с retry и таймаутами
- [ ] **Правило «1→1»**: загрузка в приёмник блокируется при несовпадении пары источник→приёмник
- [ ] **Кеш**: повторный `inspect_source`/`extract` без изменений базы не перечитывает её целиком;
      инвалидация при изменении файла
- [ ] **Verify**: после `load` сверка «источник ↔ приёмник» даёт 100% полноту или список расхождений
- [ ] Крупные таблицы обрабатываются потоково (ограничение памяти)
- [ ] Все модули покрыты unit-тестами на синтетических фикстурах + интеграционные тесты
      на копиях реальных баз (`1С_7.7`, `1C_8.1`, `1C_8.3`, read-only)
- [ ] README описывает установку, использование через Claude/Cursor и ограничения
- [ ] Единая внутренняя модель: конвейер map/transform/validate/load работает одинаково
      для любого источника (7.7 / 8.x)

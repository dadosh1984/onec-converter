## Итоги переноса

- **Перенесено**: 36 сопоставленных объектов, **4251 записей** в 27 таблицах
  приёмника (копия `workdir_83\1Cv8.1CD`).
- **Сверка**: `verify.ok=True`, `checked=4251`, `missing=[]`, `mismatched=[]`
  (все записи прочитаны без потерь).
- **Snapshot приёмника**: `workdir_83\snapshot.1CD` (откат при сбое).
- **Не перенесено**: 217 объектов источника без соответствия в приёмнике —
  между разными конфигурациями автоматический маппинг их не покрывает
  (нет целевого типа).

## Релиз 0.44.0 / 0.44.1 (опубликован)

При переносе добавлены фиксы + визуальный прогресс и выпущены релизы:
- **0.44.0** — фиксы `decode_datetime`, BLOB-base64, `_extract_8x` (named),
  `_lookup_table` (регистр 8.3) + progress-бар `TermProgress`;
- **0.44.1** — прогресс вне TTY печатает редкие узлы (старт/каждая 10%/финал),
  а не по строке на объект.
Оба опубликованы на PyPI/TestPyPI и GitHub Release (`git tag v0.44.x`).
MCP-конфиг pi указан на `.venv/Scripts/onec-converter.exe` (venv с рабочим
пакетом, т.к. системная editable-установка на этой машине ломалась).

## Обнаруженные и исправленные дефекты onec-converter

При переносе выявлены 3 дефекта кода (исправлены, см. коммит):
1. **`decode_datetime` падала** на дате-заглушке `0100-00-00` (валидная как
   «пустая» дата 1С) → exception ломал extract/query/migrate.
   Фикс: возвращать `None`, а не бросать `ValueError`.
2. **`save_json_batch/stream` падали** на BLOB-полях (`bytes not JSON
   serializable`) → фото/двоичные данные невозможно выгрузить.
   Фикс: кодировать `bytes` в base64.
3. **`_extract_8x` НЕ сопоставлял таблицы с правилами TOON по именам**
   (объекты имели тип `Таблица.*`, а не `Справочник.X`) → `migrate --rules`
   давал 0 объектов. Добавлен `named=True`: объекты с типом `kind.имя` и
   реквизитами по именам.
4. **`read_metadata` не учитывал регистр таблиц 8.3** (`_DOCUMENT625` против
   физического `_Document625`) → load не находил таблицы. Добавлен
   case-insensitive lookup `_lookup_table`.

## Добавлена функциональность: visual progress-бар

- Перед переносом в терминале (stderr) не было видно, что происходит.
  Добавлен `TermProgress` (`src/onec_converter/progress.py`): при переносе
  через `migrate --direct`/`load_direct` теперь видно живой бар — проценты,
  число перенесённых объектов, текущая таблица; по завершении — сводка
  таблиц приёмника с количеством записей.
- Вывод — в stderr, чтобы не ломать JSON stdout (машиночитаемость и MCP
  совместимы); в TTY бар перезаписывается (`\r`), вне TTY — редкие узлы
  прогресса.

## Ограничения
- Индексы таблиц приёмника не пересобираются (известное ограничение, Фаза 14);
  1С может не сразу видеть новые строки по индексируемым полям.
- HTTP-загрузки нет (коннектор не настроен) — использована прямая запись в копию.
- Перенос между **разными конфигурациями**: переносятся только пересекающиеся
  объекты; полный перенос невозможен без ручного расширения правил TOON.

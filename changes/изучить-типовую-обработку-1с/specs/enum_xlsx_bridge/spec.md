# Spec: enum_xlsx_bridge

## Назначение
Изучить типовую обработку 1С «Выгрузка и загрузка данных XML.epf» (формат контейнера 1С 8.0, не zip) как эталон формата XML-выгрузки 1С и алгоритмов переноса, и спроектировать опциональный «XML-мост 1С» для проекта onec_converter: (1) парсер XML-файла выгрузки 1С (объекты, реквизиты, ссылки-GUID, предопределённые элементы) с прямой записью в 1Cv8.1CD приёмника через write_8x; (2) генератор XML-файла 1С из данных ИБ для загрузки штатной обработкой 1С. Цель — точный перенос ссылок (GUID) между ИБ в дополнение к текстовому xlsx-мосту. Оценить усилия, риски и приоритет относительно оставшихся этапов Фазы 3 (хуки, режим ТЧ, lookup-расширения) и приёмки xlsx-моста на реальной базе. — Windows, Python 3.x

## Область

- В области: указанная возможность, поставляется тест-первой.
- Вне области: всё, что не заявлено в предложении.

## Критерии приёмки
- [x] Извлечение значений перечисления из CONFIG приёмника (порядок `_ENUMORDER`) — `enum_resolver.extract_enum_values`.
- [x] Конвертация GUID-строки CONFIG в 16 байт `_IDRREF` (layout p3+p4+p2+p1+p0) — `guid_str_to_ref`.
- [x] Индекс синоним -> ссылка (нормализация `normalize_enum_name`), позиционное соответствие с `_Enum<N>`.
- [x] Ветка `Перечисление.X` в `epf_load._resolve_ref` (синоним -> ссылка, иначе 16 нулей).
- [x] Обратная сверка link -> синоним (`EnumResolver.by_ref`); интеграция в `bridge_verify` — за рамками (мета не несёт полное имя ссылочного типа).
- [x] Тесты: извлечение, резолвинг, позиционность, e2e через мост; + integration на реальной базе 1C_8.1 (marker `integration`).
- [x] Ворота зелёные: ruff, mypy strict, pytest 605 passed.
